# Unified Semantic-Zoom Graph + Tailwind UI + vis-network Physics

## Goal

Replace the three fragmented graph views (code/module/migration) with **one unified graph** that uses **semantic zoom** (zoomed out = migration units, medium = modules, zoomed in = code symbols). Replace Sigma (static layout) with **vis-network** (animated Barnes-Hut physics). Replace custom CSS with **Tailwind CSS** for a polished, industry-standard look matching the reference page's dark-sidebar + light-graph layout.

## Decisions (confirmed with user)

- **UI**: Stay vanilla JS + esbuild; add Tailwind CSS for styling
- **Graph library**: vis-network (matching the reference page at https://chuanqi87.github.io/python-analysis/graph_viewer.html)
- **Zoom interaction**: Hybrid — camera zoom level auto-switches layers + double-click expands/collapses
- **Existing views**: All integrated into the unified graph (no separate table/overview tabs)

## Architecture Changes

### Current → Target

| Aspect | Current | Target |
|--------|---------|--------|
| Graph renderer | Sigma v3 (WebCanvas, static) | vis-network 9.x (Canvas, Barnes-Hut physics) |
| Layout | ForceAtlas2 (200 iters, then frozen) | vis-network built-in physics (continuous animation) |
| Graphs | 3 separate paths (codegraph/appgraph/migration) | 1 unified graph with 3 semantic zoom levels |
| Navigation | Hash-route tabs + page reloads | Single canvas, zoom + click to traverse levels |
| CSS | 1024-line custom styles.css | Tailwind CSS (dark sidebar + light graph, like reference) |
| Detail | Separate page per view | Floating detail panel (top-left of canvas) |

### Semantic Zoom Levels

```
Level 0 (scale < 0.5): Migration Units
  Nodes: MigrationUnitWire[] → colored by migration status
  Edges: unit→unit dependsOn
  Data: /api/migration/graph + /api/migration/ledger (loaded on init)
  Expand: double-click unit → zoom to Level 1, focus on member modules

Level 1 (0.5 ≤ scale < 2.0): Modules (ArchModules)
  Nodes: AppNodeWire[] where kind='ArchModule' → colored by unit membership
  Edges: module→module depends_on
  Data: /api/appgraph/graph (loaded on init)
  Expand: double-click module → zoom to Level 2, load code symbols
  Collapse: zoom out → return to Level 0

Level 2 (scale ≥ 2.0): Code Symbols
  Nodes: CodeGraph Node[] within focused module's dir → colored by symbol kind
  Edges: calls/references/contains between those symbols
  Data: NEW /api/codegraph/dir-subgraph?dir=<prefix>&limit=500 (lazy-loaded)
  Collapse: zoom out → return to Level 1
```

### Hybrid Interaction Model

- **Zoom-driven**: `network.on('zoom')` event → check `network.getScale()` → switch DataSet when crossing thresholds (debounced 300ms)
- **Click-driven**: `network.on('doubleClick')` → expand node to children (unit→modules, module→symbols), animate zoom to appropriate level
- **Transition**: when expanding, seed child positions near parent's position; let physics animate them into place

### Phase 3: Unified Graph View (core)

**New file:** `src/webui/client/unified-graph.ts` (~500-600 lines)

This is the heart of the change. It replaces `graph-view.ts` entirely.

**Structure:**
```typescript
// Data model: holds all three levels, loaded lazily
interface UnifiedGraphData {
  status: StatusResponse;       // /api/status — which levels exist
  migrationModel?: MigrationModel;  // Level 0
  appModel?: AppGraphModel;     // Level 1
  // Level 2 is lazy-loaded per module via dirSubgraph()
}

// Main entry point
export async function renderUnifiedGraph(container: HTMLElement): Promise<void>
```

**Key components within unified-graph.ts:**

1. **Data loading** (on init):
   - `api.status()` → determine available levels
   - If migration exists: `api.migrationGraph()` + `api.migrationLedger()` → build MigrationModel
   - If appgraph exists: `api.appGraph()` → build AppGraphModel
   - Level 2: lazy-loaded via `api.dirSubgraph(module.dir, 500)` on expand

2. **vis-network setup** (matching reference page):
   ```typescript
   const options = {
     physics: {
       barnesHut: { gravitationalConstant: -12000, springLength: 90, springConstant: 0.02, damping: 0.35 },
       stabilization: { iterations: 250 }
     },
     interaction: { hover: true, tooltipDelay: 120 },
     layout: { improvedLayout: true }
   };
   ```

3. **Level rendering** — three functions that build vis DataSets:
   - `buildLevel0Data(migrationModel)` → vis nodes (units) + edges (unit dependsOn)
   - `buildLevel1Data(appModel, migrationModel)` → vis nodes (modules) + edges (depends_on)
   - `buildLevel2Data(codeNodes, codeEdges)` → vis nodes (symbols) + edges (calls/references)

4. **Zoom-level management**:
   ```typescript
   let currentLevel = -1;
   const ZOOM_THRESHOLDS = { level0: 0.5, level1: 2.0 };
   
   network.on('zoom', debounce(() => {
     const scale = network.getScale();
     const newLevel = scale < ZOOM_THRESHOLDS.level0 ? 0
                    : scale < ZOOM_THRESHOLDS.level1 ? 1 : 2;
     if (newLevel !== currentLevel) switchLevel(newLevel);
   }, 300));
   ```

5. **Level switching** (`switchLevel`):
   - Check data availability (don't switch to a level with no data)
   - For Level 2: determine which module to focus (the one closest to viewport center, or last double-clicked)
   - Seed positions: child nodes start near parent's last position
   - Swap DataSets: `nodesDS.clear(); nodesDS.add(newNodes); edgesDS.clear(); edgesDS.add(newEdges);`
   - `network.stabilize()` to animate

6. **Node interaction**:
   - `network.on('click')` → show detail panel for clicked node (delegates to `detail-panel.ts`)
   - `network.on('doubleClick')` → expand node:
     - Level 0 unit → switch to Level 1, focus on member modules
     - Level 1 module → load code symbols via `api.dirSubgraph()`, switch to Level 2
   - `network.on('hoverNode')` / `blurNode` → highlight effect

7. **Node styling** (per level):
   - Level 0: `shape: 'dot'`, `value` by module count, `color` by migration status (grey/blue/amber/green/red), `borderWidth` by dependency count
   - Level 1: `shape: 'dot'`, `value` by symbolCount, `color` by migration unit membership (same unit = same color)
   - Level 2: `shape: 'dot'`, `value` by degree, `color` by symbol kind (function=blue, class=green, method=orange, etc.)
   - All: `font: { size: proportional to node value }`, `shadow` for important nodes

8. **Edge styling** (per level):
   - Level 0: solid arrows, colored by necessity (dev-only = dashed)
   - Level 1: solid arrows, colored by edge kind (depends_on=orange, navigates_to=blue, etc.)
   - Level 2: thin grey lines with arrows, `smooth: { type: 'continuous' }`

## Key Design Decisions

1. **vis-network over Cytoscape.js**: User explicitly referenced a vis-network page; its Barnes-Hut physics gives the animated, "alive" feel they want. No compound-node support, but we implement semantic zoom via DataSet swapping + position seeding.

2. **Position seeding on level switch**: When expanding a unit → modules, each module starts at the unit's position + small random offset, then physics animates them outward. This gives a natural "explosion" effect rather than nodes appearing at random positions.

3. **Level 2 is lazy-loaded**: Code symbols can be thousands per module. We only load them when a module is expanded/zoomed into, using the new `dir-subgraph` endpoint. This keeps init fast and memory bounded.

4. **Debounced zoom switching**: 300ms debounce prevents rapid DataSet thrashing during continuous scroll-zoom. The level only switches when zoom stabilizes past a threshold.

5. **Manual level override**: Sidebar has a "Level 0/1/2" button group that lets users manually jump levels (useful when zoom thresholds don't feel right, or for accessibility).

6. **Physics toggle**: Like the reference page, a "Physics: on/off" button lets users freeze the graph once it stabilizes (useful for screenshots or when nodes settle in a good position).
